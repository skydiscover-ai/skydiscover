# Contributing to SkyDiscover

Thanks for your interest in improving SkyDiscover. This guide covers the basics for getting set up and opening a pull request.

## Development setup

SkyDiscover uses [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/skydiscover-ai/skydiscover
cd skydiscover
uv sync --extra dev
```

## Running the tests

```bash
uv run pytest tests/ -m "not slow and not integration"
```

## Formatting and lint

We use `black` and `isort` with a line length of 100, and `mypy` for type checking. Run all
three before opening a pull request:

```bash
uv run black skydiscover/ tests/ benchmarks/
uv run isort skydiscover/ tests/ benchmarks/
uv run mypy skydiscover/
```

CI runs exactly these commands, so a green local run means a green CI run. To have them run
automatically before each commit:

```bash
uv run pre-commit install
```

The hooks shell out to `uv run`, so they use the same pinned versions as CI rather than a
separate set.

`mypy` is enforced against everything outside the baseline in `pyproject.toml`
(`[[tool.mypy.overrides]]`). That list only shrinks: if you finish typing a module, delete its
line. Please don't add to it.

## Opening a pull request

1. For anything non-trivial, open an issue first so we can agree on the approach.
2. Branch from `main`, keep commits focused, and keep the diff minimal.
3. Add or update tests for any change in behavior.
4. Make sure `uv run pytest tests/ -m "not slow and not integration"` passes and the formatters are clean.
5. Open the PR with a short description of what changed and why.

## Adding a search algorithm or benchmark

- New search algorithm: see [`skydiscover/optimize/search/README.md`](skydiscover/optimize/search/README.md).
- New benchmark: see [`benchmarks/README.md`](benchmarks/README.md#adding-a-benchmark).

## AI-assisted contributions

AI tools are welcome, but you are responsible for everything you submit. Read and understand every line, test it, and do not open unreviewed autogenerated pull requests.
